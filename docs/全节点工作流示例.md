# 全节点智能问答工作流

项目当前具备以下可视化节点：开始、结束、LLM、RAG、NL2SQL、条件分支、HTTP 工具、子工作流和循环。MCP 是独立微服务，不是独立画布节点；示例使用 HTTP 工具节点调用 MCP 的 `calculator` 工具。

示例会创建两个工作流：

```text
主工作流
开始 → LLM 意图识别 → 条件分支
                       ├─ 知识 → RAG ─────────┐
                       ├─ 数据 → NL2SQL ──────┤
                       ├─ 计算 → HTTP/MCP ────┼→ 循环守卫 → 子工作流 → 结束
                       └─ 默认 → LLM ─────────┘

子工作流
开始 → LLM 统一整理结果 → 结束
```

## 创建

前置条件：网关（8080）、工作流服务（8084）、MCP 服务（8087）已启动；已准备一个普通知识库和一个 DDL 知识库。

在 PowerShell 中执行：

```powershell
.\scripts\create-all-nodes-workflow.ps1 `
  -Token '<登录后取得的 JWT>' `
  -RagKnowledgeBaseId 1 `
  -DdlKnowledgeBaseId 2 `
  -DatabaseName 'test_ai'
```

脚本先创建子工作流，再把返回的真实 ID 写入主工作流的 `subworkflow` 节点，不需要手工修正引用。

## 试运行

- 知识分支：输入一个能由普通知识库回答的问题。
- 数据分支：输入“统计最近 7 天的用户数量”等与 DDL 知识库匹配的问题。
- MCP 分支：输入纯表达式，例如 `3*(2+2)`。
- 默认分支：输入一般问答问题。

## 当前限制

`LoopNode` 类真实存在，但当前执行引擎没有为它注册条件回边。它现在只会执行一次、更新 `__loop_iteration__` 并透传数据。因此示例把它配置为 `maxIterations=1` 的迭代守卫，避免将其误称为已经可用的多轮循环。若要真正循环，需要为循环节点增加 `continue/exit` 路由，并在图执行器中支持回边。
